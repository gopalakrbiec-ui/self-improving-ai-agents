02 · Verification

The generation–verification gap

Generating a correct answer somewhere in a sample set is not enough. The system must recognize it reliably.

Outcome Reward Model (ORM)

Scores the final solution. Cheap when final answers are automatically checkable, but sparse: a flawed derivation can get lucky, while an almost-correct derivation can receive zero reward.

trajectory → final answer → reward

Process Reward Model (PRM)

Scores intermediate reasoning steps. Dense supervision helps prune bad branches early and can guide search before the full trajectory is complete.

s₁→r₁, s₂→r₂, …, sₙ→rₙ

Training verifiers

Early verifier work on GSM8K showed that discriminating among model solutions can improve final answer selection.

Paper ↗

PRM800K

Human process supervision evaluates individual reasoning steps instead of only final outcomes.

Paper ↗

Math-Shepherd & Weaver

Automated step-level labels reduce annotation cost; verifier ensembles aim to combine weak judges and distill them into efficient evaluators.

04 · Planning & multi-step reasoning

Reasoning as controlled search

Planning changes the agent from a single trajectory generator into a controller that can explore alternatives, branch, backtrack, parallelize, and learn multi-step tool behavior.

LATS — Language Agent Tree Search

MCTS combines reasoning, acting, self-reflection, and LLM-based scoring. Branches represent alternative actions or thoughts; promising branches receive more compute.

state → {branch A, branch B, branch C} → score → expand → backtrack
Primary paper ↗

SPRINT — Parallel reasoning plans

Decomposes reasoning into independent plans that can be executed in parallel, reducing the sequential token path when the task admits useful decomposition.

problem → {plan₁ ∥ plan₂ ∥ plan₃ ∥ plan₄} → aggregate
Primary paper ↗

SWiRL — Synthetic tool trajectories

Generates and filters synthetic multi-step tool-use trajectories, then trains policies to internalize useful action patterns without live execution in every training rollout.

synthetic trajectories → filter → RL → tool-use policy
Primary paper ↗
Irreversible actions matter. Search is cheap in simulation but dangerous when actions send money, delete files, message people, or modify production systems. Real agents need approval gates, rollback, simulation, and stronger verification at commitment boundaries.

Pass@K vs Majority@K

RL may dramatically increase how often the model uses an already-known successful strategy without expanding the frontier of what it can ever solve. Majority@K can rise while pass@K moves much less.

Reward diversity

If every sampled response gets reward 0—or every response gets reward 1—the batch provides almost no relative learning signal. Dynamic sampling seeks prompts with informative reward variation.

07 · Evaluation

From benchmark scores to reliable work

The frontier shifts from “can the model answer this?” to “can the agent complete an extended piece of valuable work reliably?”

Long-horizon reliability

13.3%
P(overall) ≈ pⁿ

Why long tasks are hard

Even high local competence can collapse over many dependent actions. This is why task duration, recovery, state tracking, tool choice, and stopping policies become first-class evaluation targets.

A rare success demonstrates capability. Repeated high-probability success begins to justify delegation.

Measures what duration of human-professional task an agent can complete at a given success threshold.

08 · Future research

Beyond fixed self-improvement loops

Future systems must improve diversity, verification, task selection, continual learning, compute allocation, and efficiency—not merely scale one component.

Reasoning diversity
Multi-agent generators, critics, debaters, and specialists can reduce correlated failure and preserve exploration.
Meta-verification
Agents need to evaluate reasoning and evaluators when no trusted reference answer exists.
Self-generated tasks
Models can construct curricula near their capability frontier, creating synthetic-data flywheels.
Open-ended evolution
Novelty and diversity objectives may discover qualitatively new strategies beyond direct reward maximization.
Continual learning
Deployment could become part of training, provided updates remain stable, safe, private, and provenance-aware.
Adaptive compute
Agents should learn how much search, verification, retrieval, and revision each task is worth.
Intelligence per watt
Capability must be evaluated against energy and hardware cost as agentic workloads multiply inference calls.
Hybrid local–cloud inference
Small local models may handle routine/private work while cloud systems receive expensive, difficult trajectories.
